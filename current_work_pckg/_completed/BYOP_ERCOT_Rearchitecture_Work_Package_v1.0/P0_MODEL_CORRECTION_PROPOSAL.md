# P0_MODEL_CORRECTION_PROPOSAL — P0-1 / P0-2 模型修正方案（待研究者批准后实施）

- 日期：2026-10-20
- 依据：`BYOP_ERCOT_RUN_DECISION_AND_CORRECTION_PLAN_2026-10-20.md` 第 3、5、7.2 节
- 状态：**PROPOSAL**。本文件只提出方案，尚未修改任何代码。当前 `DEV_GU`、`R1_GW`、`R1_GK` 继续运行至结束，其结果统一标记为 `BASELINE_DIAGNOSTIC`。
- 本文所述修正**全部保持连续 LP**，不引入整数变量。

## 0. 现状（以实际代码为准）

| 位置 | 当前做法 | 问题 |
|---|---|---|
| `rearch_mech.add_dc_poi` 与 `v240_mech.add_dc` | 每个场址、每一年各有一个独立的 IT 容量变量 `S[s,p]`（compute_IT 生成器，只在该年有效），负荷曲线固定 | 各年变量之间没有约束，所以服务量可以出现 250 → 0 → 868 MW 这种下降（**P0-1**） |
| 同上 | 服务价值写成 `capital_cost = −v`（v = 2.8e6 美元/MW_IT·年），没有“已投运但部分时段供电不足”的选项 | 已接入的数据中心只能被整年撤掉，不能只在少数时段中断；而背景负荷切负荷价格为 1e4 美元/MWh，模型宁可切背景负荷也要保住数据中心（中期报告 I-5） |
| `rearch_mech.s1_offer` | 企业得到的电网报价 = **按经济最优求出的 S1** 中实际出现的 Firm POI 潮流峰值 | S1 因成本权衡少供的部分，被当成电网的物理上限，导致 S2 多建 BYOP（**P0-2**） |
| `v240_mech.extra` / `serve_cap` | 当年服务的 IT ≤（设备容量 + 自备可靠容量）/ PUE | 本身没有问题，修正后保留 |

## 1. P0-1：已投运 IT 容量跨年连续；运行中断与撤销投运分开

### 1.1 变量定义（全部为连续变量）

| 符号 | 含义 | 实现 |
|---|---|---|
| `IT_online[s,y]` | 累计已投运 IT 容量 (MW_IT) | 沿用现有 `S[s,y]`，即 `DC_<s> S<y>` 的装机容量 |
| `IT_add[s,y]` | 当年新增投运容量 | 表达式 `IT_online[s,y] − IT_online[s,y−1]`（≥ 0），只用于输出，不新增变量 |
| `IT_interrupt[s,t]` | 已投运 IT 在时段 t 的运行中断功率（设施侧 MW） | 新增生成器 `DC_<s> intr<y>`（载体 `dc_interrupt`），可用于全部时段，上限为当年设施负荷 |
| `IT_served[s,y]` | 当年按能量折算的服务量 | 输出指标：`IT_online − 中断电量 / (单位 IT 年设施电量)` |
| `IT_unserved[s,y]` | 未交付的需求 | `D[s,y] − IT_online[s,y]`（尚未投运部分）+ 中断折算部分，两项分开报告 |
| PCLR 中断 | 条件供电在触发时段的削减 | 保留现有 `dc_curtail`（只在触发时段可用，按小时预算）。它与 `dc_interrupt` 分开记账：前者是合同约定的中断，后者是供电不足造成的非计划中断 |

### 1.2 约束

1. **跨年连续**（新增，加在 `extra_rearch` 中，对每个场址、每对相邻年份）：
   - 若当年需求不低于上一年（`D[s,y] ≥ D[s,y−1]`）：`IT_online[s,y] − IT_online[s,y−1] ≥ 0`
   - 若需求因取消情景下降：`IT_online[s,y] − IT_online[s,y−1] ≥ −(D[s,y−1] − D[s,y])`，即只允许按取消量减少。
   - 两种情况都只有变量和常数，是线性约束。
2. **投运须有可靠供电**：保留 `serve_cap`。`IT_online ≤（设备容量 + POI 升级量）/ PUE + 自备可靠容量`，即没有设备或自备电源就不能计为投运。
3. **运行中断的价格低于背景负荷切负荷**：`dc_interrupt` 的边际成本取损失算力价值，约 460 美元/MWh，远低于背景负荷切负荷的 1e4 美元/MWh。这样供电不足时先中断数据中心，与 ERCOT 对大负荷“先削减”的规则一致，同时修正 I-5。
4. **不得损害既有用户**（新增，修正 I-5）：在有新增 AIDC 的情景中，每个母线、每个时段的背景负荷切负荷不超过 S0 的同一数值，即 `shed[b,t] ≤ shed_S0[b,t]`（S0 的值在求解后读入，作为常数）。
5. **服务价值的写法**：把 `−v` 作为投运容量的价值保留，同时把中断电量按同一价值折算后计入成本，两者口径一致：一个 MW 投运了但全年都中断，价值为零。

### 1.3 对现有结果的影响

S1 中 ABI 的 250 → 0 → 868 MW 会变成：要么从 2027 年起持续投运、2028 年部分时段中断，要么推迟到 2029 年才投运（取决于两种做法的成本）。延迟统计、COD、S2 的 BYOP 需求都会变化，**所以当前三组算例的服务轨迹全部只具有诊断价值**。

## 2. P0-2：物理最早可交付的纯电网基准 `S1_GRID_EARLIEST`

### 2.1 定义（严格 Speed-First）

在与 S1 完全相同的物理可行域内求解，包括：POI 设备与升级工期、Batch Zero 审批日期、KVL 网络与已承诺工程、ERM 行、公共电源工期、背景负荷、竞争负荷，以及第 1 节的跨年连续和“不得损害既有用户”约束。此外，**不允许 `dc_interrupt`**（Firm 服务必须全时段送达）。

- **阶段 A（逐年，最早年份优先）**：对年份 y = 2026, …, 2031 依次求
  - A1：最大化当年各场址投运容量之和 `Σ_s IT_online[s,y]`，得到最优值 `T*_y`，然后加约束 `Σ_s IT_online[s,y] ≥ T*_y(1−1e−6)` 固定下来；
  - A2：在 A1 的结果下，最大化各场址中最低的满足率（max-min 公平）：`max z`，约束 `IT_online[s,y] ≥ z·D[s,y]`（对所有 `D[s,y] > 0` 的场址），固定 z 后进入下一年。
  - A2 解决了“同一年总可交付量在多个场址之间怎么分”的不唯一问题，而且保证同一份公共供电不会被重复分给多个场址（各场址共享同一个网络和 ERM 行）。
- **阶段 B**：在阶段 A 固定的轨迹下，最小化公共系统社会资源成本。

这就是验收要求 5 中所说“严格 Speed-First 的具体定义”。它与 S2 开发商的规则（逐年先保速度、再保成本）同构，区别只在于优化的是公共系统，以及有多场址公平这一步。

### 2.2 报价改用物理最早结果

- `s1_offer` 的输入从经济最优 S1 改为 `S1_GRID_EARLIEST`：各场址各年的 Firm 报价 = 阶段 B 解中的 Firm POI 进口峰值，并记录对应的约束来源（设备、审批、网络、ERM 的对偶值和松紧状态）。
- 经济最优 S1 保留为对照情景 `S1_ECON`，即现在的 S1，用于计算“经济上选择少供”的数量：`S1_GRID_EARLIEST − S1_ECON`。
- 延迟归因（xPOI/xUP/xRA/xPROC/xALL）改为以 `S1_GRID_EARLIEST` 为基准。

### 2.3 求解实现与计算量

逐年做 A1、A2 共 12 次 LP，再加阶段 B，若每次都完整求解，代价是现在的 13 倍左右（每个设置约 5 小时）。方案：

1. 用 linopy 导出 gurobipy 模型（`m.to_gurobipy()`），利用 **Gurobi 原生的分层多目标**（`setObjectiveN` 设优先级，对 LP 自动固定上一层的最优值），一次 `optimize()` 完成 A1→A2→B。仍是连续 LP，Gurobi 会复用前一层的解作为起点。预计为单次求解时间的 2–4 倍。
2. 若分层多目标不稳定，退回到 linopy 中逐层求解（与 `private_stage_sf` 相同的写法），并给每层设置 `BarConvTol` 并保存检查点。
3. **同时缩小模型**（第 4 节），把单次求解时间从约 25 分钟降下来。

## 4. 计算量控制（与 P0 一起实施，不改变模型含义）

- 现在的模型为 280 万–365 万变量、每个情景 10–50 分钟。其中背景机组按“母线 × 机组类型 × 退役年份”分组，加上 ERM 储备变量，是变量数的主要来源。在不改变容量和成本的前提下合并同类分组，预计可明显减少变量数。实施前会先做诊断，确认合并前后 S0 的目标值不变。
- 并行方式：每个设置按 `--case-group` 拆成 3–4 个子进程（S0/S1_ECON；S1_GRID_EARLIEST + 归因；S2 链；S3 链），每个 4–6 线程，使 12 个物理核心均匀满载。
- 求解参数：试验 `BarHomogeneous=1` 与 `NumericFocus`，因为目前内点法普遍需要约 160 次迭代。

## 5. 新增单元测试与小算例验收

**单元测试**（合成网络，L2 上用 Gurobi 运行，每项几分钟内完成）：

1. `test_online_monotone`：无取消时 `IT_online` 逐年不下降；有取消时最多减少取消量。
2. `test_interrupt_not_decommission`：供电不足年份的结果是部分时段中断，投运容量保持不变；中断电量和中断损失单独记账。
3. `test_no_harm_background`：有数据中心时每个时段的背景切负荷不超过 S0。
4. `test_earliest_ge_econ`：`S1_GRID_EARLIEST` 每年的投运量 ≥ `S1_ECON`。
5. `test_earliest_monotone_in_options`：给网络增加可选扩建项后，最早可交付量每年都不减少（验收要求 2）。
6. `test_joint_allocation`：两个场址共用一条受限线路时，各自的投运量之和不超过线路可送达量；A2 的 max-min 分配可以复现。
7. `test_offer_traceable`：S2 报价等于 `S1_GRID_EARLIEST` 的 Firm 进口峰值，并带有约束来源标签。
8. 现有 8 项测试继续通过。

**小 ERCOT 算例**（使用同一 64 节点骨干网，2026–2029 四年、每年 1 个抽样周、3 个 POI、G-K 设置），用旧代码和新代码分别求解对照，验收条件：

| 检查 | 通过标准 |

| 纯 LP、全部最优 | 整数变量为 0 |
| 跨年连续 | 无取消时任何场址的 `IT_online` 都不下降 |

## 8. 需要研究者决定的事项

1. 是否批准第 2.1 节的严格 Speed-First 定义，特别是 A2 用 max-min 公平在多个场址之间分配同一年的可交付量。备选：按排队顺序（请求年份 → 场址编号）分配。
2. 运行中断的价格是否取损失算力价值（约 460 美元/MWh），以及“不得损害既有用户”约束是否按 S0 逐母线、逐时段取值。
3. I-4（S0 远西部切负荷）的处理：纳入 2026–2029 年已承诺的 TPIT 项目，还是在 2026–2029 年再做一次可送达性校准。两种做法都会改变 S0，需与 P0 一起实施。
