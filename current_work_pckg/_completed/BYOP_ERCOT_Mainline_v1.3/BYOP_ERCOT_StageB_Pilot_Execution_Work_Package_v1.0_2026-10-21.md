## 1. 与《论文顶层设计.md》的关系：当前能验证什么

论文长期目标是解释开发商追求 Speed-to-Power 的私人投资如何改变公共电网建设及长期资产利用。本阶段是其 **2026–2031 年 ERCOT 最小机制验证**，不是完整 2026–2050 年论文计算。

| 机制 | 本阶段研究问题 | 最小可接受结果证据 | 本阶段明确不声称 |
|---|---|---|---|
| **M1：速度—成本 / 并网时滞** | S1 是否因物理、POI 或工期条件延迟？S2 自主 BYOP 是否提高 IT 交付速度？ | 每个母线×年份申请量、已交付量、延期；S2 的 BYOP 技术与实际 COD；S1/S2 对比 | 不直接测出 Speed Premium 的完整临界曲线；不精确复现每个 ERCOT 项目审批 |
| **M2：私人投资—公共扩张反馈** | S2 BYOP 投资是否替代、提前或增加公共电源/储能/输电/POI 投资？ | S0、S1、S2、S3 的公共资产容量和投运年；同一资产口径下 S2−S1、S1−S0 对比 | 不提前推断 2050 年路径依赖与搁浅损失 |
| **M4：私人—社会效率偏离** | 对相同已交付 IT 服务，企业自选 BYOP 是否比社会协调方案耗费更多真实资源？ | **最终** S2 与 `S3_mS2` 每母线×年份交付量严格配对；两者真实资源成本比较 | 不把购电支付/税收转移作为社会真实成本；不拿不同服务量的低成本直接判定“效率更高” |
| **M3：长期路径依赖** | 本阶段只准备基础 | 保存资产批准年份、COD、位置、技术、容量和运营记录 | 暂不进行 2032–2050 年滚动投资、退出及搁浅仿真 |

**固定设计，不得在本工作包中改动：** ERCOT TAMU 64-bus；Epoch AI 的 **8 个** AIDC 母线；一个统一开发商；`mid` 需求；2026–2031 年逐年规划；单一 `G-REAL` 背景；RICE、标准 SOFC、Aero OCGT、WIND、PV、4h BESS；S2 先逐年最大化投运 IT，再最小化私人成本；共享电网物理约束；无整数变量；技术参数按 v1.3 文件读取。

**阶段性边界：** 当前 S2 是严格 Speed-First 的多阶段线性优化，并不是通过扫不同延期价格获得临界曲线。顶层设计中 M1 的完整速度溢价临界条件留待后续。现阶段最重要的是证明（或否证）电网延迟 → 自建选型 → 公共投资反馈的逻辑链。

## 3. 唯一要求的运行前代码修复：S2 最终迭代与 M4 的一致性

### 3.1 已确认的风险

目前 `workflow/byop/model/rearch_mech.py` 中的 S2 迭代按以下方式命名：

```python
r2 = go('S2' if it == 1 else f'S2_it{it}', ...)
```

但 `saved['S2_service']` 在循环结束时保存**最后一轮**公共电网实际交付量，而 `workflow/byop/post/collect_mainline.py` 的 matched-service 成本比较固定取 `scenario == 'S2'`。若出现两轮以上，可能误把**第一轮** S2 成本与**最后一轮**的 `S3_mS2` 对比。

这会直接损害论文 M4 的有效性，属于**值得在首轮正式运行之前修复的代码问题**；无需重写模型或增加求解次数。

### 3.2 必须实现的最小方案

采用下面的**语义规范**，实现形式可由执行者选择最简安全方法：

1. **保留每次迭代的原始结果**：`S2`、`S2_it2`、`S2_it3` 等原标签及求解/交付性日志可保留供追溯，不覆盖原始证据。
2. 在最后一次**通过开发商计划—公共电网交付性核验**的 S2 迭代完成后，显式认定一个唯一 `S2_final`（或在所有正式汇总中稳定地将这轮映射为 `S2`，二选一，不允许混用）。
3. 正式汇总与图表中的 **S2 交付量、BYOP 技术/容量、公共发电及输电投资、社会/私人成本、对偶值、POI 账本、资产台账**必须全部来自**同一轮**。若用 `S2_final` 新名称，所有结果文件与后处理均统一采用该名称；必要时保留 `S2_selected_iteration` 元数据。
4. `S3_mS2` **只**固定最终 S2 公共电网**实际交付的** 8×6 母线—年度 IT 量，而不是开发商提案、第一轮交付或预设申请量。
5. 如经过最多 3 轮仍无法达到当前约定的 `gap_IT_MW <= max(0.5, 1e-3*planned_IT_MW)`：保留调试结果，但 `S2_CONVERGED = False`、`SCIENTIFIC_USE = BLOCKED`，**不得对 M2/M4 作有效科学结论**。不额外增加迭代次数或编造收敛结果。
6. 修正后处理的匹配检查：**母线×年份键完全一致、每键唯一、2026–2031 共 48 条数据、两边无缺失或非数值、最大绝对差 ≤ 0.5 MW IT**；任一失败均拒绝输出“有效 matched-service 成本差”（可以保留诊断值，须标为无效）。
7. 避免汇总中把中间 S2 迭代**重复相加**为公共投资、BYOP 装机或总成本；中间迭代单列调试表即可。若只进行一轮，`S2_final` 应与该轮数值逐项一致。
8. 更新 `MAINLINE_GATE_CHECKS.csv` 和 `MAINLINE_CASE_MANIFEST.json`：包含 `selected_S2_iteration`、`s2_converged`、`matched_service_48_keys_present`、`matched_service_max_abs_gap_IT_MW`、`scientific_use`。不得把关键检查缺失（`None/NaN`）当作自动通过。

**测试（全部无需求解器）：**

- 用**合成两轮 S2** 结果验证：`S2_it2` 才是最终轮；`S3_mS2` 与第二轮匹配；正式报告的 S2 投资、成本和服务全部取第二轮，第一轮仅留在诊断表。
- 验证仅有一轮时结果无变化；验证 48 条记录缺一条、出现重复键、超过 0.5 MW 差值、最终交付性核验失败时均标 `BLOCKED`。
- 保持全部现有 `QA-PARAM/QA-COD/QA-FIRM/QA-SPACE/QA-LP` 测试通过；模型整数变量数仍为零。

**允许改动文件：** 优先限于 `workflow/byop/model/rearch_mech.py`、`workflow/byop/post/collect_mainline.py`、对应测试；必要时更新报告/工作包索引。除修复一致性所必需的逻辑外，**不得修改实际优化约束、技术数据或经济目标**。

## 4. 只调整运行组织：先不做归因分析

### 4.1 新增简洁运行入口

当前 `workflow/byop/run/run_mainline.sh` 的 `run` 默认调用 `--attribution`，会额外求解 `xPOI/xUP/xRA/xPROC/xALL`。首轮无需支付这部分计算成本。建议最小增加以下命令（可自行选择合理名称，但语义必须一致）：

| 命令 | 求解内容 | 用途 | 是否需要研究者运行授权 |
|---|---|---|---|
| `tests` / `struct` / `gate` | 现有无求解器测试与门控检查 | 修复验证、生成预审记录 | 不需要求解授权（`gate` 只检查） |
| `step0` | 现有 ERM 校准 + S0 最小修复增容校准 | 提供共同可信的 ERCOT 基准 | **需要** |
| `pilot_s01`（新增） | 仅 `S0` 和 `S1_EARLIEST`；**不带** `--attribution` | 先确认基准可解、真正存在什么延期 | **需要** |
| `pilot_core`（新增） | `S0、S1_EARLIEST、S3、S2、S3_mS2`；**不带** `--attribution` | 最快得到 M1/M2/M4 主线结果 | **需要** |
| `attribution`（可选，后置） | S1 严格基准及 `xPOI/xUP/xRA/xPROC/xALL` | 只在主线结果值得深入解释时运行 | **需要** |
| `run`（保留） | 完整情景 + 归因（现有入口） | 完整研究报告 | **需要** |

实现原则：

- 不为此建立另一套模型或不同技术参数；所有调用仍复用现有 `rearch_mech.py --mainline`、同一 G-REAL、同一 ReEDS2 表、同一 `mid` 需求、同一技术和时间窗口。
- `pilot_s01` 可以显式使用 `--scenarios S0 S1_EARLIEST`；这是**受控分阶段试运行**，不代表正式工作包删除了 `S3_mS2`。`pilot_core` 应执行配置中的**全部五个必需主情景**。
- 运行中的主要输入和版本保持相同；只允许通过场景选择、归因开关与 case-id 区分试运行。`pilot_core` 与随后 `run` 应可核对相同情景的参数与求解口径。
- 各阶段使用**不同独立输出目录与 case-id**，避免旧的 `ledger.csv`、`S2_developer_modes.csv`、`case_manifest.json` 混入后续结果。不要让两个任务并发写同一路径。
- 在 `run_mainline.sh` 提供 `pilot_s01`、`pilot_core` 等入口的同时，补充不调用求解器的命令组装测试（确保无 `--attribution`、场景列表正确）；不需要对整个求解脚本重构。
- 后处理对 `pilot_s01` 缺少 S2/S3 的情况应输出 `PARTIAL_PILOT`，而非假装全情景科学检查通过；`pilot_core` 必须有完整 M4 检查。

### 4.2 运行前的审计—授权步骤（不可省略）

1. 执行方在现有功能分支（或明确记录的新功能分支）完成第 3、4 节修复；运行**无求解器测试**；提交 GitHub，不合并 `main`。

## 5. Stage B 分阶段运行与停止条件

### B0 — 仅修复代码与测试（无求解器）

**进入条件：** Stage A 分支存在，最新 SHA 及输入可读取。

**交付：** 第 3 节 S2 结果引用修复；第 4 节分步入口；新无求解器回归测试；GitHub 修订提交；更新 pre-run manifest 与审计报告。

### B1 — `step0`：公共电网校准（获批准后）

**目的：** 校准既有/承诺电力系统，不把模型原有缺陷错误归因于 AIDC。沿用现有 ERM 校准及 S0 最小增容校准；不改变校准成本原则，不为营造拥堵而调参。

**至少输出与检查：**

- 每一投资年 S0 全网及母线背景切负荷量；单列继承爬坡负荷的切负荷；`no_harm` 约束的基准作用。
- S0 校准增加的输电 MW、地理位置、年度可用日期、与 AIDC 八母线的相对位置；是否出现规模异常或明显不合实际的“无成本公共容量”。
- ERM 校准的数值、收敛状态、显式使用的基准 `*.nc` 哈希和模型提交 SHA。
- **若校准失败、异常扩大网络，或没有可解释的基准供电可靠性，STOP，不进入 B2。** 先报告原因，给出不超过 1–2 个有依据的最小修复选项供研究者决定。

### B2 — `pilot_s01`：Grid-Only 的真实延期来源

**目的：** 确定 M1 的输入物理机制在真正求解后是否生效，**不要求一定出现延期**。

**必要输出：** 全部 8 个母线 × 2026–2031 年：`requested_IT_MW`、`served_IT_MW`、`delay_IT_MW`、POI 设备容量/升级 MW 与 COD、 Firm 进口量、公共电网投资、背景切负荷、LP 求解状态。报告 G-REAL 中现有 KVL / ERM / POI / 程序约束是否可能绑定；未做单因素归因时不要宣称已量化各自贡献。

**判定：**

- 若 S1 的 IT 延期量非零：核对是否与 POI/程序、上游或资源充裕度具备可解释关系；尤其标记 Abilene、Shackelford、Red Oak、Temple 的真实求解表现，不能照搬先验预测。
- 若全部母线几乎无延迟：这仍是**真实结果候选**；停止并检查模型是否因为 E0 提前开放、无限进口、校准过度增容或 Firm 错误认证而失真，**不直接修改线路容量制造差异**。
- 若严重切负荷、约束不满足、任何 LP 无最优解、数值单位/能量平衡明显异常：**STOP** 并生成异常诊断，不继续 S2。

### B3 — `pilot_core`：M1、M2、M4 主线联合验证

**前提：** B1/B2 验收通过、保持同一代码/参数/基准。

**正式求解情景：** `S0`、`S1_EARLIEST`、`S3`、`S2_final`（S2 开发商及其公共复核，可经有限次迭代）、`S3_mS2`。`S2_final` 是最终标签语义，并非额外新的优化情景。

**M1 核验：**

- 比较 S1 与 S2_final 的已交付 IT 容量和累计延期 MW_IT-year；按母线与年度拆分。
- 每母线输出 GO_F/GO_C/GF/IS 的实际供电模式、Firm/Conditional 取电、电量与 BYOP 技术、数量、COD。
- 检查 BYOP 是否真在符合建设工期后投运；如 S2 速度无改善，原样报告，不人为改变技术工期。

**M2 核验：**

- 分技术/母线/年度对照 S1、S2_final、S3 的公共发电、储能、线路扩建、POI；提供 S2_final−S1 变化、与 S0 的基准差异。
- 检查是否有公共投资被 BYOP 替代、公共投资被提前/推迟，或双重建设的迹象。**只对 2031 年内的资产投资作结论**；不把期末低利用率推断成长期搁浅。

**M4 核验：**

- S2_final vs S3_mS2 的母线×年交付 IT 精确配对（48 个唯一键，最大偏差 ≤ 0.5 MW IT）。
- 仅比较社会真实资源成本：公共/专属资产真实年金与残值假设、燃料、运行、真实负荷损失等；企业购电支付、补贴及其他转移不得重复计入社会资源成本。
- 同时给出 S3 自由服务量的结果，但明确这是**不同交付结果**，不能直接以成本高低判定效率。

**全部情景通用硬性验收：**

1. `termination=optimal`、整数变量为 0、优化输入 SHA 与批准 SHA 一致。
2. 现有用户 `no-harm` 不违反、已投运 IT 不无故逐年下降、每母线服务量不超过申请量。
3. 数据中心逐时电力平衡、BESS SOC、燃气日 MDQ、POI 同时 Firm+Conditional 上限、关键压力时段限制满足。
4. S2 最终公共电网**能够交付**开发商承诺容量；任何未收敛情况不能用于正式科学结论。
5. matched-service 不缺行、不重复、不跨迭代错配；真实资源成本账本可追溯。
6. `SCIENTIFIC_USE = ALLOWED` 仅在上述有效性测试完成时允许；未知、缺失、失败都不得默认为通过。

**结果解释的关键注意：** 若 S2 与 S3 物理可选资产相同，只有目标函数/决策主体不同，得到相同结果也是有效发现；不要求凭空出现非零社会效率损失。

### B4 — 归因分析（可选、后置）

**只有 B3 获得有意义且通过质量验收的结果时**，才建议调用单因素放松：`S1E_xPOI`、`S1E_xUP`、`S1E_xRA`、`S1E_xPROC`、`S1E_xALL`。据此诊断 POI、上游输电、资源充裕度、程序/工程日期的影响。

- 单因素放松的交付量增益不是互斥贡献，**不得线性相加当作完整延期分解**。
- 若 B3 没有 BYOP 提速或公共投资反馈，先分析最根本的约束/目标选择，不急着加五项求解。
- 如果 B3 已足够回答 M1/M2/M4 的初步科学问题，B4 可延后，以便先撰写阶段性结论。

## 6. 结果异常处理原则：只修真实错误，不追逐预期结论

| Stage B 现象 | 应先检查 | 明确不得做 |
|---|---|---|
| S1 无并网延迟 | E0 的资格日期、POI 与上游实际约束、S0 校准幅度、背景负荷与 Firm 认证 | 随意把线路缩小、把 E0 改为零 |
| S2 不选择 BYOP | S1 是否已有足够进口、BYOP 最早 COD、气源 MDQ、真实私人成本、Speed-First 目标 | 人为降低燃气/燃料电池成本，或允许未核实 SOFC Fast |
| S2 选择 BYOP 却不能公共侧交付 | 认证时段、权利重复预留、S2/S1 报价、迭代收敛、年度 COD | 直接忽略 `S2_consistency.csv` |
| M2 公共投资变化很小 | 时间窗口、容量扩张活跃程度、公共建设工期、期末投资和 S0 共同基准 | 为制造反馈随意改变公共网架 |
| S2/S3 社会成本差异难解释 | 48 键 matched-service、最后迭代选取、社会成本是否重复计入转移/损失 | 直接用不同服务量的情景比较“效率” |
| LP 不收敛、求解资源不足 | 数值尺度、重复索引、错误固定服务量、冗余约束及必要的求解器日志 | 在未报告原因前反复跑完整归因矩阵 |

**对于确需修正的实现错误：** 先列出最小复现证据、出错代码位置、模型影响、测试补丁和新 SHA，再向研究者汇报。所有改动都必须保持连续 LP，并区分“修复程序错误”和“变更研究假设”。
