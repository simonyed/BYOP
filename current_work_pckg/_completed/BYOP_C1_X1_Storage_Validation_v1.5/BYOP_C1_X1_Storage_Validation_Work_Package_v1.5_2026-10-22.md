## 1. 目标、范围与求解边界

本轮回答两个问题：

1. 在校准容量固定时，保存网络时对 x、r 的缩放，改变了多少切负荷与拥塞？
2. 在原经济目标与总供电量基本不变时，最小化储能吞吐量能否消除大量同时充放电？

按顺序执行两次年度 3h LP：先 C1-X1，再在 X1 最优解上求储能二级目标。本工作包的执行范围只包括这两次目标求解。另建专用配置和日志，明确引用本文件及其 SHA；保留原 C1 结果和正式门控。

- 不重跑原校准 LP，不重跑 BASE / CALIBRATED 原四个案例，不新增压力窗口或参数扫描。
- 不启动 S0/S1/S2/S3、B3 或正式容量扩张。
- 不改变历史机组、未来 AIDC、继承负荷、POI、天然气、技术成本、ERM 或 VOLL。
- 新结果独立存储，不能覆盖 baseline prepared.nc、原始网络或旧 C1 结果。
- 两次为有效目标求解预算；失败尝试与重试另记实际调用次数。必要的数值重试仅限同一算例、不改变物理集合；沿用已经验证的求解器设置，避免无理由重试。若持续失败，保留完整证据并停止依赖步骤，不启动替代算例。

## 3. 第一次 LP：C1-X1，校准容量＋原始阻抗

建议 case_id：`C1_X1_RAW_IMPEDANCE`。

### 3.1 构造规则

- 从既有 CALIBRATED 网络复制诊断对象，保留所有线路 s_nom 与 s_max_pu。
- 按稳定的线路 ID，从原始未校准网络取得 x、r；在既有 18 条增容线路上恢复原始 x、r，其余线路保持不变。
- 不使用当前行顺序关联，不重新计算或舍入容量，不更改拓扑和线路长度，不增删并联线路。
- 对照现有 CALIBRATED C1，除上述 x、r 外，机组集合、负荷、可用率、储能、快照、权重、成本、VOLL 35,685 USD/MWh、全局约束处理、切负荷变量及求解精度均保持一致。
- 固定所有容量，不存在 p_nom / s_nom / e_nom 建设变量；无 2026 起 S0CAL Links。

构建逐线审计表：raw 和 calibrated 的 s_nom、x、r，以及 X1 使用值、是否增容线、是否恢复阻抗。断言 X1 与 CALIBRATED 的容量完全一致；阻抗差异恰好对应预期线路。

### 3.2 目标与结果

使用原 C1 运行成本＋诊断切负荷成本目标，全年 2,920 时段、权重 3，储能年度循环边界不变。只接受 `status == 'ok'` 且 `termination == 'optimal'`。

在进入第二阶段前立即保存：原经济目标表达式、目标分项、最优值 F*、切负荷总量 E*，以及全部原始运行变量和经济目标下的价格/对偶。

### 3.3 如何解释

| 对比 | 可以回答什么 |
|---|---|
| 既有 CALIBRATED 与 X1 | 当前固定容量、成本和运行边界下，阻抗处理的影响 |
| X1 与原校准 residual 102.2 MWh | 尚混有目标函数、切负荷价格和小额增容截断等差异，不能单独归因 |

输出切负荷差额、母线和月份分布、最大/最长事件、逐线路潮流和饱和时长的变化。重点解释 p620 系列、p630 2 及 TL12、TL69、TL40、TL26、TL43、TL63 等线路。

若 X1 大幅改善，可确认阻抗处理在该模型对照中有实质影响；不能仅以“是否接近 102 MWh”作为通过标准。若差异很小或仍有残差，原样报告，不自动追加原校准重跑。

降低某条线路阻抗并不保证它在每个时段都承担更多潮流。应由全网结果验证潮流如何重分配，不把这一假说写成一般定律。

## 4. 第二次 LP：在 X1 上最小化储能吞吐量

建议 case_id：`C1_X1_MIN_STORAGE_THROUGHPUT`。

### 4.1 保持第一阶段经济目标和总服务量

保留 X1 的全部物理约束和资产容量，使用 X1 第一阶段的原经济目标表达式 F(x)，增加：

\[
F(x) \le F^* + \epsilon_F
\]

推荐默认成本容差：`epsilon_F = max(1 USD, 1e-8 * abs(F*))`。记录实际数值与求解器可行性容差；若数值不可行，先排查表达式、权重和精度，不无声放宽。

为保持总交付量可比，同时约束总切负荷 E(x)：

\[
E^*-\epsilon_E \le E(x) \le E^*+\epsilon_E
\]

下界不低于零。推荐 `epsilon_E = max(0.001 MWh, 1e-8 * abs(E*))`；E 的计算必须使用与第一阶段相同的时间权重、单位和切负荷变量。该约束用于隔离调度退化，不代表要求正式模型固定切负荷。

### 4.2 新目标

\[
\min\sum_{s,t} w_t\left(p^{store}_{s,t}+p^{dispatch}_{s,t}\right)
\]

对全部电池逐单元、逐时段计算，使用物理充放电量与时段小时权重；不另乘效率修正，不以净功率代替吞吐量。

- 不修改储能或风光边际成本，不引入二进制变量或充放电互斥 MILP。
- 尽量复用 X1 在内存中的最优模型；不得为了得到第一阶段目标而再次求解一遍 X1。
- 如果实现需要重建约束，使用已保存的 F*、E* 和同一输入构造第二阶段，验证原目标表达式完整一致；只进行这一次二级目标求解。
- 避免在替换目标后丢失原 F(x)；用第二阶段解重新计算原经济成本并独立校验边界。

### 4.3 判断标准

比较第一/第二阶段的原经济成本、总切负荷、逐母线和逐事件切负荷、弃电、储能损耗、重叠充放电、吞吐量、SOC 和线路指标。

- 重叠大幅减少且原成本与总切负荷在规定容差内：支持“原解中存在可以消除的退化充放电”。
- 若线路或切负荷位置变化，应明确披露；即使总量相同，也不能声称所有运行结果不受影响。
- 若重叠仍明显，检查是否存在局部能量消纳、其他约束或数值问题；不得自动认定都是错误，也不得自行追加 MILP。
- 必须精确最优终止、功率/能量平衡及两项边界检查通过，才能用于上述判断。

第一阶段价格与第二阶段对偶分目录、分字段保存。第二阶段的对偶对应吞吐量目标及新增约束，不能标为原经济调度电价。

## 5. 两阶段完整结果保存

结果建议存入 `workflow/results/BYOP/C1_X1_STORAGE_V15/`，每阶段独立目录。大型结果遵守仓库既有数据管理规则，不强制提交 GitHub；小表、代码、配置、日志和报告提交并附大文件 SHA 与可访问位置。

每阶段至少保存：

| 类别 | 变量/证据 |
|---|---|
| 储能 | 每单元 p_store、p_dispatch、SOC、效率、初末边界及单元到母线映射 |
| 发电 | 每机组实际出力、可用出力、p_min_pu/p_max_pu 与弃电 |
| 网络 | 逐线 p0/p1、容量、有效限额、x/r、饱和状态 |
| 缺电 | 逐母线逐时段切负荷，事件、月度及年度汇总 |
| 目标与价格 | 原经济目标各项、原目标值、F*/E*、容差、当前求解目标、原经济阶段的价格/可获得对偶 |
| 可复现性 | 网络/代码/配置/输入 SHA、环境版本、求解选项、开始结束时间、状态、日志、调用/重试分类 |

如某变量按当前求解接口无法获得，记录原因；不能把缺失值填零。主运行变量导出不完整时不能声称完成储能机制验证。

指标沿用同一电池同一时段的 `min(p_store, p_dispatch)` 计算重叠量，采用一致阈值和权重。同时检查逐单元状态转移及年度循环；首时段结束 SOC 不必等于末时段 SOC，不能用两者简单相等代替状态方程。

时间坐标同时保留原模型时间与 2025 Native Load 源行/HE 标签，保留 DST 和 24:00；不声称已转换为 UTC。
