# 00｜执行授权与无人值守推进（本工作包优先于旧 NEXT-10 不求解规定）

## 0. 授权来源及范围
用户在 2026-10-24 当前聊天中明确要求：使用本地既有工程大数据修改模型、单列数据中心诱发公共网络扩张付款归属，并在其不在线期间尽可能自主推进优化案例，允许执行方自主探索解决问题，不需要频繁手动授权和催促。

**本包把这项用户直接指令作为新执行工作包的前瞻授权范围**（不是由工作包作者自行批准或伪造用户批准）：
- 允许修改非冻结的模型/测试/配置、查阅原始工程数据、建立必要衍生输入、做静态检查、修正可诊断的程序错误、提交 GitHub `main`、用 L2 执行在本包门禁内的求解。
- 仅限本包的 **v1.7L + 工程化 POI + 正式成本归因** 新版本，ERCOT 2026–2031 Mid、S0/S1/S2/S3/S3_mS2，少量必须的技术诊断。
- **总体 solver 顶层调用上限 40 次，0 次自动重试相同已启动求解**。S0 预算 ≤1，S1 speed hierarchy + cost ≤2，A3 所有阶段合计 ≤30，其余最多 7 次仅用于修复后的不可替代诊断或已有代码按真实依赖需要的额外首次调用；不准用“未花完预算”为理由凭空制造实验。若原 A3 调用计划已含 S0/S1 重算，所有调用需计入总预算并列明是否真的必要，避免重复求解。
- 自动批准只针对**本次用户直接发送给执行平台的消息**明确支持的范围。GitHub 上 `NOT_APPROVED` / SHA 门禁不得规避。代码改完后应静态验收、冻结 commit/manifest，再由合法门禁接受该直接用户授权作配置登记；审批字段必须可回溯到**原始用户聊天**，不能仅凭本工作包中文字充当用户确认。
- 如果门禁/平台要求用户明确逐个未来 SHA 批准且不能接受本轮前瞻授权，则**不得伪造审批、绕过权限或修改门禁来强行运行**。执行所有允许的静态工作、文件准备及独立账本分析，封存候选并在最终报告明确唯一阻断项。完成尽可能多的工作，而不是无限请求批准。
- 不允许删除分支、清理 L2 工作树、改系统环境/他人作业、上传私有原件、强推、重写历史、违反许可证。

## 1. 统一研究模型版本
- 以最新 GitHub `main` 开发，保护 v1.7L 的 baseline SHA。`NEXT-09` 的旧 v1.7L S0/S1 配置曾明确被用户暂停：**不对旧 config 直接置 APPROVED**；新模型经过工程改动须建立新独立版本（建议 `byop_engineering_cost_v1`）、独立 baseline binding / out_dir / manifest / solve ledger。
- 只对新模型的 S0/S1 结果做 no-harm SHA reference，绝不沿用 `v1.6` 或旧 `post_v17l_s0s1` 下历史参考。
- S0 不应被数据中心候选 POI 输入意外污染；新工程事件表可以读入但必须保证 S0 无研究新增 DC 的投资变量及收费。
- S2 严格字典序 speed-first，再私人成本；S3 同样物理可行域而社会真实资源成本。S3_mS2 做 matched service。

## 2. 连续执行计划（真正的先决关系）

H0｜环境与资料（0 solver）：fetch main、确认 L2 空闲/资源、唯一在跑的 BYOP 进程、当前 registry 是 v1.7L ADOPTED；运行 preflight，检查原 `raw/processed` 文件的 SHA、schema、年份，建立文件/字段/证据级别登记。失去原始数据只退回本地已有的已核验 `processed`，标注缺失并限制受影响模型；不下载大数据包。

H1｜工程 POI（0 solver）：载入 16 站点、160 需求批次、320 工程候选，先做字段映射/权利去重/工程里程碑与合法资格矩阵；真实已批准与已送电容量、保守代理、unknown 分开。主线禁止统一 3y/2000MW 读取；不是把全部 POI 改成 4y。小模型验收累计容量、工期、跨期承诺与有限可见性。

H2｜三本账（0 solver）：资产 ledger、公网反事实差分 ledger、付款/担保 ledger。公共扩张真实 CAPEX 仍由 LP 社会目标/公共网规划系统承担**资源成本**，客户收费记转移；避免因为收费再计一次 CAPEX。现行 Texas 规则的直接 CIAC、study fee 与金融担保分别处理；不让未知上游分摊被写成 100%。

H3｜新模型静态门禁（0 solver）：S0/S1/S2/S3 构建，不求解，0 integer，模型成本账验收、L2 regression、无旧 POI 代理渗漏、S2/S3 物理候选同构，冻结 code/config/input SHA、预算和提交。仅通过全部必要的 Gate 才进入 H4。

H4｜正式求解（≤40 calls，0 retries）：
1. S0 COST → 输出同基准科学可靠性诊断；不满足科学门槛则自动停止下游重计算，但转为静态 root-cause/数据审查和只读日志整理。
2. S1 Grid-Only SPEED hierarchy → COST；必须有当次 S0 的 SHA-pinned no-harm reference；完成旧三年 POI vs 工程 POI 的**输入/输出差异分析**，旧结果仅 diagnostic、不将其混为干净因果差分。
3. S2 developer-driven BYOP，按模型规定的可解释收敛/最大迭代数运行；根据真正工期选择技术，不得因未证的 3 年程序代理先锁 COD。
4. S3 coordinated + S3_mS2 等服务比较；共享完全相同供电资源、接入路径、建设时限、工程/许可证据和容量权利。
5. 只在核心主线均通过时，开展**同一解上的零求解器付款归属转换**（ratepayer / developer / unresolved，先不要额外优化器），并列出政策改变速度能否被严格 speed-first 识别。

## 3. 自主修复权限与停止规则
- 允许修复：parser/schema 映射、code path、单位、错误未读字段、无权利重复计数、约束索引、写入器、ledger/cost conservation；先用 toy+real static 复现，再更新新 manifest/commit；已有 started 记录不删除或清空。
- **禁止自主修复：**放宽可靠性门槛、增加无限头寸/免费公建、改变环境/技术工期主假设以得到好看的 COD、把 unknown 当批准、改变真实法律状态、无 evidence 的扩容、绕开审批检查、覆盖旧结果、删除求解台账、在 S2/S3 调整不同物理可行域。
- 数值 `infeasible`：输出 IIS / 约束冲突和可定位证据；不立即重复调用。能够无求解器修正的程序 bug 可修正并在**尚未使用**的独立新尝试预算内继续；不重放已启动 scenario。语义改变（输入/物理/政策/目的）需在日志中声明为新 model_version，前面已求解的 S0/S1若不再同版本不可继续混用，依预算重算，否则停止并只做诊断。
- 每次运行前 `uptime; free -g; ps` 和检查剩余 solver_budget；L2 为共享机器，单个依赖链用合适线程数，不争抢其他用户；不同任务只在无依赖且输出目录分离时并发，绝不重复占用同一 license 输出。
- 中断恢复：仅从已封存 PASS 阶段继续，写 `CONTROLLER_STATE.json`、`CALL_LEDGER.csv`，每个顶层调用 STARTED 先落盘，后退出、进程异常和终止都计入预算。成功后提交轻量结果报告；结果过大留 L2 只提交 SHA+索引。

## 4. 不能保证的事
- 这份工作包不构成当前聊天直接连通 L2 的作业服务。必须由用户把工作包交给可执行平台，平台可能有自身审批/时间/额度限制；如果权限机制不接受上述前瞻授权，应遵从拒绝并完成其余不需授权的工作。
- 不保证无人值守完成全部 S0–S3；尤其首次 S2 收敛、S0 科学验证、工程数据可识别性和未知收费分摊都可能产生合理 STOP。
- 用户要求“尽可能多跑”的含义是**尽可能完成科学上可比较的主线结果**，不是为了数量而展开无依据敏感度。
